## 2025-02-27 - Hardcoded Developer Secret Key in Production
**Vulnerability:** The Flask application could start in production with the default 'dev' `SECRET_KEY` if the `SECRET_KEY` environment variable was missing or empty, leading to weak session signing and potential session manipulation attacks.
**Learning:** Checking for configuration presence (like `SECRET_KEY = os.environ.get('SECRET_KEY')`) in the class-based configuration (`ProductionConfig`) does not prevent the application from starting without one, and doesn't explicitly throw an error. Relying on default fallbacks in base configuration (`Config`) can mask missing environment variables in production.
**Prevention:** Explicitly validate the presence and strength of security-critical configurations (like `SECRET_KEY`) inside the application factory (`create_app()`), specifically scoping the check to production environments (`app.debug is False and app.config.get('TESTING') is False`) to fail-fast and prevent insecure deployments, without breaking local development.
